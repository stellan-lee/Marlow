# Marlow 的 Codex CLI 兼容性设计

## 1. 背景

Marlow 此前要求 Codex CLI 精确等于 `0.159.2`。当本机 PATH 指向 `0.172.0` 时，运行时和登录入口都会在启动前拒绝它。共享同一个 Codex 安装的用户每次升级都可能遇到这个问题，即使新版本仍能满足 Marlow 的集成要求。

精确版本最初为实验性的 app-server 接口提供了可复现的验证基线。Marlow 依赖实际生效的沙箱、审批、独立凭据存储和工具发现配置。

## 2. 目标与范围

- 允许 Marlow 使用能够满足其运行要求的 Codex CLI，实际版本用于诊断。
- 让 CLI、Gateway、登录和健康检查对同一台机器上的 Codex 给出一致且可操作的诊断。
- 本设计聚焦 Codex 二进制选择、启动验证与诊断。旧 profile 配置和历史数据迁移分别按现有迁移流程处理。

## 3. 设计

优先使用 profile 显式指定的 `runtime.codex.binary`，其次从 PATH 查找。读取并报告实际版本，使用严格配置启动 app-server，复用现有握手、有效配置和工具发现检查。关键协议字段、权限配置或隔离设置无法验证时，应在允许对应的推理或工具操作前失败，并报告具体阶段和原因。

将验证归到现有 Codex 传输与会话层。运行时入口、登录和 doctor 使用一致的二进制选择与诊断语义。登录允许尚未认证的 profile 完成登录流程，诊断分别报告找不到二进制、启动或兼容性失败、未登录。CLI 和仓库文档描述实际兼容条件。

## 4. 备选方案

继续维护版本白名单可以明确列出已验收的版本，但每次上游升级都需要发布 Marlow 才能继续使用新二进制。设置最低版本维护量较小，但版本号无法识别实验接口在之后版本中的行为变化。以具体运行要求为准可以在出现差异时给出更直接的错误，同时允许能够通过检查的新版本启动。

## 5. 风险与待验证事项

握手成功只证明协议入口可用。新版仍可能改变沙箱、审批、原生工具发现、旧会话恢复或凭据处理的语义。运行时能检查的约束需要明确检查，依赖实际行为的约束需要用真实二进制和临时 profile 验证。遇到兼容差异时，根据实测结果决定所需的适配范围。

设计阶段在 macOS 上用临时 profile 验证了 `0.172.0` 的严格配置启动、`initialize`、`config/read`、`skills/list`、无凭据的 `account/read`、授权的 `command/exec` 和运行环境重新初始化。

## 6. 使用与维护影响

使用 PATH 的安装可以跟随系统更新。需要控制升级节奏的操作者可以在 profile 指定独立二进制。测试中记录实际 Codex 版本，用确定版本重现回归。启动验证复用现有进程和握手，避免增加单独的探测服务。

## 7. 验收

- 用真实的 `0.159.2` 和 `0.172.0` 在受支持平台运行相关协议和集成测试，并记录版本与平台。
- 用本地 Responses 测试服务验证完整对话、会话恢复、Marlow MCP 工具调用、审批允许和拒绝、沙箱文件范围及 profile 隔离。
- 验证 CLI 和 Gateway 共用的运行路径，确认登录入口和 doctor 能区分兼容性问题与缺少凭据。
- 验证缺失或不符合要求的关键能力会在对应操作前失败，日志能指出失败阶段和实际版本。

实现验证使用真实的 `0.159.2` 和 `0.172.0`，在 macOS arm64 和允许嵌套用户命名空间的 Linux arm64 容器上各版本通过 226 项相关测试。模型响应来自本地测试服务。
